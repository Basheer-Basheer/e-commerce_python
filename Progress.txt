E-COMMERCE ORDER MANAGEMENT SYSTEM
===================================

MAIN RULE:
----------

Do NOT move to the next phase until the current phase is:

1. Implemented
2. Tested
3. Understood
4. All tests are passing
5. Marked as [DONE]

The goal is NOT to finish quickly.

The goal is to understand why every design decision exists.

IMPORTANT:

This project is NOT a copy of Fleet Rental.

We will reuse some known concepts,
but every major phase should introduce
at least one new concept or deeper understanding.


==================================================
PROJECT GOAL
==================================================

Build a medium-sized E-Commerce Order Management
System using Python.

The system should allow:

- Customers
- Products
- Inventory
- Shopping Cart
- Orders
- Order Items
- Discounts
- Payments
- Notifications
- Reports
- SQLite database
- CLI application

Main workflow:

Customer
   |
   v
Shopping Cart
   |
   +---- Product
   |
   v
Checkout
   |
   +---- Discount
   |
   +---- Payment
   |
   +---- Inventory
   |
   v
Order
   |
   v
Notification

==================================================
PHASE 16 - INVENTORY RESERVATION
==================================================

IMPORTANT NEW BUSINESS CONCEPT.

When checkout starts:

Stock
 |
 v
Reserve stock
 |
 v
Payment
 |
 +---- SUCCESS -> Confirm reservation
 |
 +---- FAILURE -> Release reservation

DESIGN DECISION (set during planning review, confirm again here):
reserve_stock() / release_stock() / confirm_stock() will live in
a dedicated InventoryService, NOT directly inside Product.
Reason: reservation is not just "change a number" like
increase_stock()/decrease_stock() in Phase 4 - it's a multi-step
workflow that depends on order/checkout state and can be undone
(released), so it belongs at the service/orchestration level,
not inside the Product entity itself. We'll re-examine this
decision together once we start implementing, not just take it
as given.

Implement:

[ DONE ] confirm_stock()

[ DONE ] Failed reservation
[ DONE ] Payment failure releases stock
[ DONE ] Successful payment confirms stock
[ DONE ] Insufficient stock
